## 全局 GUI 无界面测试补充规则

以下规则适用于所有项目中 Agent 执行的 GUI 相关操作；既有 GUI 重启条款只约束获准重启时的操作方式，不构成自动重启要求。

1. 开发、构建、调试及自动化测试期间，默认禁止启动或重启可见 GUI 窗口，包括测试、脚本、子进程、构建钩子间接打开的浏览器、应用或文件管理器。
2. 优先使用 headless、offscreen、虚拟显示或 mock 等无界面测试模式；例如浏览器使用 headless，Qt 测试按需使用 QT_QPA_PLATFORM=offscreen。测试参数仅作用于对应命令或测试进程，不设置影响日常使用的全局环境变量。
3. 禁止自动重启 GUI、激活或置顶窗口、抢占桌面焦点；不得为了验证普通代码修改而反复启动 GUI。
4. 仅在全部代码修改和无界面验证完成后，确实需要界面验收时，才最多允许启动或重启一次当前任务的 GUI；这不是必做步骤。后续再次启动须由用户明确要求；用户明确要求的手动操作不计入 Agent 自动验收额度。
5. 必须使用真实界面但当前无法在上述边界内完成的测试，应说明限制、未执行项目及验证缺口；无界面测试通过不能替代真实界面验收，不得虚报测试通过。
6. 本规则仅约束 Agent 自动操作，不影响用户手动启动、重启或使用程序；不得为实施规则而修改项目业务逻辑、应用启动行为或用户桌面配置。
7. 配置重复执行时，应先检查本区块及已有等效条款，仅追加缺失规则，不得重复追加。

## GUI 验收权限与任务边界

- 无界面测试规则同样约束测试之外的 shell、PowerShell、临时脚本、打包冒烟、截图及窗口检查；不得绕过测试隔离入口在用户桌面启动应用。
- 只读审查、分析、计划和子代理任务禁止启动、关闭、重启、激活或置顶用户桌面的 GUI。子代理只报告界面验证缺口，由主代理统一处理验收。
- 较早任务中的“打开 GUI”“合并后打开”等指令，不得自动沿用到后续审查、新任务或子代理任务。继承的会话历史不构成当前 GUI 操作授权。
- 确有必要时的“完成后最多一次”是整个任务共享的上限，不是每个子代理、Worktree、构建产物或每轮修复各一次。主代理应记录是否已启动；不确定额度是否已用时，不自动再次启动。
- 先检查当前实际 Worktree 是否具备无界面测试隔离；不得因 main 已修复而认定旧 Worktree 也安全。不具备隔离时只做可确认安全的检查并报告缺口，不直接运行真实 GUI 测试。
